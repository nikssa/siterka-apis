# Adding data-testid Attributes to Sencha ExtReact Components

## Overview

The `Datatable` component has been enhanced to support automated testing by adding `data-testid` attributes to its tab buttons. Due to the nature of Sencha ExtReact components, a custom helper function approach was implemented to properly set these attributes on the underlying DOM elements.

## The Challenge with Sencha ExtReact Components

Unlike standard React components, Sencha ExtReact components (such as `Button`, `Container`, `SegmentedButton`) don't directly accept `data-testid` as props. These components generate complex DOM structures and require special handling to add custom attributes to their rendered elements.

### Standard React Component (Won't Work):
```jsx
// ❌ This doesn't work with Sencha ExtReact Button
<Button data-testid="my-button" text="Click me" />
```

### Sencha ExtReact Component Structure:
```jsx
// ✅ This is how we need to handle Sencha components
<Button 
  text="Click me" 
  ref={setDomAttributes({ 'data-testid': 'my-button' })} 
/>
```

## Solution: Custom Helper Function

### The `setDomAttributes` Helper Function

```javascript
// helper function for setting data-testid attributes to DOM elements (DOM elements generated by Sencha components)
export function setDomAttributes(attributes = {}) {
  return btn => {
    const dom = btn?.cmp?.el?.dom;
    if (dom) {
      Object.entries(attributes).forEach(([key, value]) => {
        dom.setAttribute(key, value);
      });
    }
  };
}
```

### How It Works

1. **Returns a Ref Callback**: The function returns a callback function that will be called when the component's `ref` is set
2. **Accesses Sencha's DOM Structure**: It navigates through Sencha's component structure (`btn.cmp.el.dom`) to reach the actual DOM element
3. **Sets Attributes Safely**: Uses native `setAttribute` to add the desired attributes, with safe navigation to prevent errors
4. **Flexible Attribute Support**: Can set any attributes, not just `data-testid`

### Sencha Component DOM Structure

```
Button Component
└── btn (Sencha component instance)
    └── cmp (component wrapper)
        └── el (element wrapper)  
            └── dom (actual DOM element) ← We target this
```

## Implementation in Datatable Component

### Before (No Testing Support):
```jsx
<Button
  text={t('Event')}
  value="event"
  pressed={(tabName || 'event') === 'event'}
/>
```

### After (With data-testid Support):
```jsx
<Button
  text={t('Event')}
  value="event"
  pressed={(tabName || 'event') === 'event'}
  ref={setDomAttributes({ 'data-testid': 'att-event-tab' })}
/>
```

## Test ID Naming Convention

| Button Text | data-testid Value |
|-------------|-------------------|
| Event | `att-event-tab` |
| Daily | `att-daily-tab` |
| Entry Method | `att-entry-method-tab` |
| Ticket Type | `att-tickettype-tab` |
| Mask/Qualifier | `att-maskqual-tab` |
| Price Level | `att-pricelevel-tab` |
| Device | `att-device-tab` |
| Section | `att-section-tab` |
| Scan Rate | `att-scanrate-tab` |

**Naming Pattern**: `att-{tab-name}-tab`
- `att-` prefix for "attendance" report
- kebab-case for the tab name
- `-tab` suffix for clarity

## Benefits for Testing

### 1. **Automated Test Reliability**
```javascript
// Tests can now reliably find and interact with buttons
const eventTab = screen.getByTestId('att-event-tab');
const deviceTab = screen.getByTestId('att-device-tab');
```

### 2. **Independence from UI Text**
- Tests won't break if button text is translated or changed
- More stable than selecting by text content

### 3. **E2E Testing Support**
```javascript
// Cypress, Playwright, or other E2E tools can use these selectors
cy.get('[data-testid="att-event-tab"]').click();
await page.click('[data-testid="att-device-tab"]');
```

### 4. **Clear Test Intent**
- `data-testid` attributes make it clear which elements are intended for testing
- Improves test readability and maintainability

## Error Handling

The helper function includes robust error handling:

```javascript
const dom = btn?.cmp?.el?.dom;
if (dom) {
  // Only set attributes if DOM element exists
}
```

This prevents errors when:
- Component is not yet mounted
- Sencha component structure differs
- DOM element is not available

## Usage Guidelines

### Do Use For:
- Interactive elements that need testing (buttons, form inputs)
- Elements that users will click or interact with
- Components where text content might change

### Don't Use For:
- Static display elements
- Elements already easily selectable by other means
- Every single DOM element (use sparingly)

### Best Practices:
1. Use descriptive, kebab-case names
2. Include component/feature prefixes (`att-` for attendance)
3. Be consistent with naming patterns
4. Document the test IDs for team reference
